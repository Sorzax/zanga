# خوارزمية السكوربورد — Java / Spring Boot / PostgreSQL

هذه خطة تنفيذ للباك إند وليست خدمة منشورة. عميل `getLeaderboard()` في الواجهة جاهز للقراءة بعد تشغيل الخدمة وتفعيل `config/api.js`.

## السلوك المقترح

- لكل طالب حساب ومعرّف من السيرفر. استخرج `userId` من جلسة الدخول، ولا تقبله من جسم الطلب.
- لكل سؤال معرّف ثابت مثل `net-q0000`. امنح نقاط السؤال مرة واحدة لكل مستخدم. الإعادة تظل متاحة للتدريب.
- الإجابة الصحيحة: `10 × min(combo, 5)` نقطة. الخاطئة تصفّر الكومبو. السيرفر يحفظ الكومبو ويحسب النقاط.
- الترتيب العام يجمع سجل الجوائز من السيرفر. ترتيب المادة يرشّح الجوائز حسب المادة. عند تساوي النقاط استخدم وقت آخر جائزة ثم معرّف المستخدم لترتيب ثابت، وحدد هذه القاعدة للمستخدم عند بناء شاشة الترتيب.
- النقاط المحلية القديمة لا تُستورد إلى الترتيب العام؛ يستطيع صاحب المتصفح تعديلها.

بنك الأسئلة الحالي مخصص للتدريب ويضم الإجابة في ملفات الواجهة. الاختبار التنافسي يحتاج مسارًا يعتمد على بنك السيرفر، ولا يرجع مفتاح الإجابة ضمن سؤال لم يُحل بعد. لا تتعامل مع هذا الموقع كاختبار مراقب أو نظام درجات جامعية.

## الجداول الأساسية

| الجدول | أهم الأعمدة والقيود |
| --- | --- |
| `app_user` | `id UUID PRIMARY KEY`, `display_name`, بيانات الدخول |
| `question` | `id TEXT PRIMARY KEY`, `subject`, `topic`, `prompt`, `options JSONB`, `correct_option_id`, الشرح، `active` |
| `quiz_session` | `id UUID`, `user_id`, `subject`, `status`, `combo`, `created_at`, `expires_at` |
| `session_question` | `session_id`, `question_id`, `position`, ترتيب الاختيارات، `answered_at`, `selected_option_id`, `is_correct`; مفتاح مركب للجلسة والسؤال |
| `answer_request` | `user_id`, `request_id UUID`, بصمة الطلب، `response JSONB`; قيد `UNIQUE(user_id, request_id)` |
| `xp_award` | `id UUID`, `user_id`, `question_id`, `subject`, `xp`, `awarded_at`; قيد `UNIQUE(user_id, question_id)` |

أضف المفاتيح الخارجية والفهارس على `xp_award(user_id)` و`xp_award(subject, user_id)`. احتفظ بإجابات الدخول والرموز والمفاتيح في الباك إند فقط. بالنسبة لكلمات المرور استخدم مشفّر كلمات مرور مخصصًا مثل BCrypt/Argon2 عبر مكتبة الأمان، ولا تستخدم SHA-256 وحدها.

## إنشاء جلسة

```text
POST /api/quiz-sessions
body: { subject: "net", count: 20 }

1. تحقق من تسجيل الدخول ومن حدود العدد والمادة.
2. اختر أسئلة فعّالة من قاعدة البيانات.
3. أنشئ جلسة مرتبطة بالمستخدم وتنتهي بعد مدة محددة.
4. خزّن ترتيب الأسئلة والاختيارات داخل session_question.
5. أرجع sessionId والأسئلة مع optionId ونص الخيار، دون correctOptionId.
```

يمكن أن يكون `questionId` هو المعرّف الثابت، وأسماء الاختيارات القادمة من السيرفر يجب أن تكون مستقرة ضمن الجلسة. لا ترسل رقم الإجابة في القائمة العشوائية وحده؛ أرسل `optionId`.

## تصحيح إجابة ومنح النقاط

```text
POST /api/quiz-sessions/{sessionId}/answers
body: { questionId: "net-q0000", optionId: "o2", requestId: UUID }

داخل معاملة واحدة (@Transactional):
  userId = المستخدم من الجلسة الموثقة
  اقفل quiz_session بـ SELECT ... FOR UPDATE
  تأكد من مالكها وحالتها وتاريخ انتهائها

  لو requestId مسجل لهذا المستخدم:
      لو بصمة نفس الطلب مطابقة: أرجع الرد المحفوظ
      وإلا أرجع 409

  اقرأ session_question المطلوبة وتأكد أنها في الجلسة
  تأكد أن السؤال هو التالي غير المجاب حسب position
  لو السؤال مجاب بالفعل: أرجع نتيجته المحفوظة دون جائزة أخرى
  تحقق من أن optionId ضمن خيارات السؤال

  correct = optionId == question.correct_option_id
  combo = correct ? session.combo + 1 : 0
  احفظ الإجابة ووقتها والكومبو

  earnedXp = 0
  لو correct:
      candidateXp = 10 * min(combo, 5)
      INSERT INTO xp_award (..., xp = candidateXp)
      ON CONFLICT (user_id, question_id) DO NOTHING
      لو تم الإدراج: earnedXp = candidateXp

  كوّن الرد من earnedXp وcorrect والشرح ومجموع الجوائز
  خزّن الرد والبصمة تحت requestId
  لو انتهت الأسئلة: أغلق الجلسة
  COMMIT
```

قفل الجلسة يرتب إجاباتها المتزامنة، والقيد الفريد على الجائزة يمنع منح نقاط السؤال نفسه عبر جلستين مختلفتين. لا تفصل تسجيل الإجابة عن الجائزة أو عن رد `requestId` في معاملات منفصلة. إذا فشلت المعاملة تُعاد كلها، دون حالة نصف محفوظة.

## قراءة الترتيب

```http
GET /api/leaderboard?subject=all&page=1&limit=20
```

الرد المتوافق مع عميل الواجهة:

```json
{
  "entries": [
    { "rank": 1, "userId": "UUID", "displayName": "Sora", "xp": 240 }
  ],
  "page": 1,
  "hasMore": false
}
```

هذا مثال لعقد البيانات فقط، ولا توجد أسماء أو نقاط تجريبية معروضة داخل التطبيق.

الاستعلام يجمع `SUM(xp)` من `xp_award`، ويطبق ترتيبًا ثابتًا قبل الترقيم والتقسيم إلى صفحات. أرجع مصفوفة فارغة إذا لا توجد جوائز، ولا تعرض البريد أو بيانات الدخول. استخدم `limit + 1` لمعرفة `hasMore`، وحدّ أعلى 100 عنصر لكل صفحة.

## أول خطوات التنفيذ

1. أنشئ مشروع Spring Boot بخدمات Web وValidation وSecurity وData JPA، وتعريف اتصال PostgreSQL.
2. أنشئ الجداول بقيودها عبر migration، ثم مستودعات البيانات وخدمات الجلسات والتصحيح والجوائز.
3. صدّر بنك الأسئلة الأولي بالأمر التالي، ثم استورده إلى قاعدة البيانات عبر مهمة خاصة بالباك إند:

```bash
node scripts/export-questions.mjs > questions.seed.json
```

4. ابدأ بالدخول ثم إنشاء الجلسة ثم الإجابة ثم قراءة الترتيب. إذا الواجهة والباك إند على نطاقين مختلفين، اسمح بـCORS لنطاق واجهتك المحدد. عند استخدام جلسات Cookie طبّق حماية CSRF للطلبات التي تغيّر الحالة.
5. فعّل العميل واضبط عنوان الخدمة في `config/api.js`. ابنِ شاشة الترتيب حول حالات تحميل ونجاح وقائمة فارغة وخطأ، واستخدم `textContent` لأسماء المستخدمين.
6. اختبر جوابين متزامنين للسؤال، وجلستين للمستخدم نفسه، وإعادة `requestId`، ومحاولة سؤال خارج الجلسة، وتغيير optionId، وانتهاء الجلسة. لا تعتبر الخدمة جاهزة حتى تمر اختبارات منح النقاط تحت التزامن.
