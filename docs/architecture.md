# خريطة المشروع

مصادر التطوير مقسّمة إلى ES Modules: `main.js` يبدأ التطبيق، و`navigation.js` يختار المادة، ووحدة المادة تجمع المحتوى والمختبر ومولّدات الأسئلة. `activateSubject` يبدّل المادة الحالية، ووحدات الدروس والاختبارات تقرأ حالتها من `core/state.js`.

`npm run build` يجمع نواة التطبيق داخل إغلاق خاص في `assets/js/runtime/app.js`، ويجهز سكربتًا مستقلاً لكل مادة يجمع بياناتها ومختبرها. النسخة التي يشغّلها المتصفح تستخدم سكربتات عادية وتحمل المادة بإضافة عنصر `script` عند الطلب. لذلك لا تعتمد على `import()` أو `fetch()` لقراءة ملفات المشروع عند فتح HTML مباشرة. يبقى كائن الحالة `S` ثابت الهوية وتُبدّل حقوله عند تغيير المادة، فتقرأ مختبرات المواد حالة المادة الحالية الصحيحة.

`index.template.html` مصدر الصفحة. البناء ينتج `index.html` وفيه بطاقات المواد الست مسبقًا. `boot.js` يراقب بدء التشغيل ويعرض رسالة قابلة للفهم إذا لم يكتمل تحميل النواة. روابط سكربتات التشغيل تحمل بصمة محتواها لتحديث النسخة المخزّنة في المتصفح عند رفع تعديل جديد.

`save()` يحتفظ بالمفاتيح القديمة ويرسل حدثًا داخليًا لتحديث الإحصاءات. التخزين لا يعرف تفاصيل الواجهة. `effects.js` يرسم مؤثرات الإجابة لفترة قصيرة فقط؛ لا توجد خلفية متحركة أو حلقة رسم تعمل أثناء الخمول.

## إضافة أو تعديل محتوى

كل سؤال داخل `Q` يتبع الشكل الأصلي:

```js
[chapter, topicId, prompt, [correctAnswer, ...otherAnswers], explanationAr, explanationEn, hot, generated]
```

الاختيارات تُخلط للطالب. لا ترتّب أو تحذف عناصر `Q` القديمة؛ الأخطاء المحفوظة تشير إلى رقم السؤال. أضف الأسئلة الجديدة في آخر القائمة، وحدّث عداد المادة داخل `data/catalog.js` عند تغيير العدد. الاختبارات تحفظ بصمات المحتوى الأصلي؛ غيّر بصمة الحقل المعدّل فقط بعد مراجعة تعديل المحتوى المقصود، ولا تعِد توليد جميع البصمات لمجرد تجاوز فشل اختبار.

كل درس له `id` ثابت و`ch` موجود في `CHS`. سجل `TOP` يُبنى من الدروس عند إنشاء وحدة المادة. صور الدرس داخل `FIGS` تشير إلى مسارات من جذر الموقع، مثل `img/net_9c0c_3.webp`.

## فصل الباك إند لاحقًا

اترك التدريب المحلي كما هو، وأضف مسار اختبار تنافسي مستقل يتلقى الأسئلة ويصححها عبر السيرفر. واجهة `getLeaderboard()` موجودة لقراءة الترتيب. لا توجد كتابة تلقائية إلى API في النسخة الحالية.

لا توجد مكتبات واجهة أو حزم تثبيت خارجية مطلوبة. سكربت البناء يستخدم Node فقط، والحزمة تتضمن مخرجاته جاهزة. خادم Node داخل `scripts/` للتطوير والمعاينة فقط؛ الاستضافة تخدم الملفات الثابتة مباشرة.
